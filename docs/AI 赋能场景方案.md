## 一、现状盘点

### 已有 AI 能力（已实现）

| 场景 | 现状 | 成熟度 |
|------|------|--------|
| 评测集 AI 生成 | Persona 批量生成 + 单条候选答案生成 | ✅ 可用 |
| AI 自动标注 | 四维评分（准确性/完整性/相关性/安全性） | ✅ 可用 |
| AI 修复建议 | Fixer 模块诊断 bad case | ✅ 后端有 |
| LLM-as-Judge | 单点/对比/参考评判 | ✅ 可用 |
| 指标评测 | 6 项指标（相关性/忠实度/幻觉/完整性/毒性/偏见） | ✅ 可用 |
| Prompt 优化 | 迭代优化 + 元提示优化 | ✅ 后端有 |
| 数据增强 | 8 种策略（同义词/回译/噪声/改写等） | ✅ 后端有 |
| 合成数据 | 6 种策略（改写/变体/对抗/边界/组合/LLM） | ✅ 后端有 |
| 报告 AI 分析 | 失败模式聚类/能力画像/改进建议 | ✅ 后端有 |

**关键问题：后端能力多，前端 UI 缺失严重，AI 能力没有串联成业务流。**

## 二、AI 赋能场景清单（按业务链路）

### 场景 1：智能评测集生成（增强）

**现状问题：** 只能基于场景描述生成，缺乏"从已有数据中挖掘"和"从线上问题中沉淀"的能力。

**AI 赋能方向：**

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **线上 Bad Case 自动沉淀** | 监控生产环境用户对话，AI 自动识别 bad case，一键转入评测集 | P0 |
| **对话日志挖掘** | 分析历史对话日志，AI 自动提取高频问题、长尾问题、边界问题，生成评测用例 | P0 |
| **竞品对话逆向生成** | 输入竞品智能体的对话记录，AI 逆向生成对应评测用例 | P1 |
| **难度自适应生成** | AI 根据已有评测集的难度分布，自动补充薄弱难度区间的用例 | P1 |
| **对抗性用例生成** | AI 针对已评测的智能体弱点，定向生成攻击性/边界性用例 | P1 |

---

### 场景 2：智能评测执行（增强）

**现状问题：** 评测执行是机械的"输入→调用→记录"，缺乏智能调度。

**AI 赋能方向：**

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **智能用例筛选** | AI 分析历史评测结果，自动筛选出"最有区分度"的用例子集，减少无效评测 | P0 |
| **动态评测策略** | AI 根据智能体类型自动选择评测维度和权重（客服侧重安全性，代码侧重准确性） | P0 |
| **评测预算优化** | AI 预测达到统计显著性所需的最小用例数，节省 API 调用成本 | P1 |
| **增量评测** | AI 对比新旧版本，只跑可能退化的用例，而非全量重跑 | P1 |

---

### 场景 3：智能评测分析（核心缺失）

**现状问题：** 评测结果只有数字，缺乏深度洞察。

**AI 赋能方向：**

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **失败模式自动聚类** | AI 对 bad case 自动分类（理解偏差/知识缺失/格式错误/逻辑错误等），生成失败模式分布图 | P0 |
| **能力雷达图自动生成** | AI 基于评测结果生成智能体能力画像（擅长什么、弱项在哪），可视化展示 | P0 |
| **根因分析** | AI 分析每条 bad case 的根本原因，给出可操作的修复建议（改 prompt/加知识/调参数） | P0 |
| **跨版本对比洞察** | AI 自动生成版本间变化的自然语言分析报告（哪些能力提升了、哪些退化了、为什么） | P1 |
| **竞品对标分析** | AI 将自家智能体与竞品在相同评测集上的表现做对比，生成差距分析 | P1 |

---

### 场景 4：智能修复闭环（增强）

**现状问题：** Fixer 模块有后端服务，但修复建议和修复执行没有串联。

**AI 赋能方向：**

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **Prompt 自动改写** | AI 根据 bad case 分析，自动改写 system prompt，生成多个候选版本 | P0 |
| **知识库自动补充** | AI 识别知识缺失类 bad case，自动生成知识条目建议，人工确认后加入知识库 | P0 |
| **修复效果预评估** | AI 在应用修复前，预测修复后的预期提升幅度，帮助决策 | P1 |
| **一键修复 + 自动验证** | 应用修复方案后自动触发回归评测，形成"诊断→修复→验证"闭环 | P0 |

---

### 场景 5：智能标注增强（增强）

**现状问题：** 自动标注只有四维评分，缺乏细粒度和多策略。

**AI 赋能方向：**

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **多维度细粒度标注** | AI 不仅给总分，还逐句/逐段标注（哪些句子准确、哪些有幻觉） | P1 |
| **标注冲突自动检测** | AI 检测人工标注与 AI 标注的分歧项，标记需要仲裁的 case | P1 |
| **标注质量自动评估** | AI 评估标注员的一致性，识别"标注质量差"的标注员 | P2 |
| **少样本学习标注** | 人工标注少量样本后，AI 自动完成剩余标注（主动学习） | P1 |

---

### 场景 6：智能 Prompt 工程（新增）

**现状问题：** Prompt 管理只有 CRUD 和版本控制，缺乏智能化。

**AI 赋能方向：**

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **Prompt 自动优化** | AI 基于评测结果自动迭代优化 prompt，多轮搜索最优版本 | P0 |
| **Prompt 模板推荐** | AI 根据任务类型自动推荐 prompt 模板和 few-shot 示例 | P1 |
| **Prompt 安全扫描** | AI 检测 prompt 中是否存在注入漏洞、信息泄露风险 | P1 |
| **Prompt 成本优化** | AI 分析 prompt 的 token 消耗，建议精简方案降低成本 | P2 |

---

### 场景 7：智能监控与告警（增强）

**现状问题：** 告警只有阈值触发，缺乏智能预测。

**AI 赋能方向：**

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **异常检测** | AI 学习历史评测数据分布，自动识别异常波动（非固定阈值） | P1 |
| **退化预测** | AI 基于趋势预测未来可能的质量退化，提前预警 | P2 |
| **告警智能降噪** | AI 对告警事件去重、聚合、优先级排序，减少告警疲劳 | P1 |
| **根因告警** | 告警触发时 AI 自动附带根因分析，而非只报"通过率下降" | P1 |

---

### 场景 8：智能报告与决策（增强）

**现状问题：** 报告只有数字和图表，缺乏决策支持。

**AI 赋能方向：**

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **自然语言报告** | AI 将评测数据转化为可读性强的文字报告（替代纯数字报表） | P0 |
| **决策建议** | AI 基于评测结果给出决策建议（是否上线/需要哪些改进/优先级排序） | P0 |
| **趋势预测** | AI 基于历史数据预测未来质量趋势 | P2 |
| **智能对比** | AI 自动生成多版本/多智能体的对比洞察（而非只是数据表格） | P1 |

## 四、技术实现要点

### AI 调用架构

```
┌─────────────────────────────────────────┐
│           AI 能力层                      │
│  ┌──────────┐  ┌──────────┐            │
│  │ 分析引擎 │  │ 生成引擎 │            │
│  │(聚类/根因)│  │(用例/Prompt)│          │
│  └──────────┘  └──────────            │
│  ┌──────────┐  ┌──────────┐            │
│  │ 标注引擎 │  │ 预测引擎 │            │
│  │(评分/细粒度)│ │(趋势/异常)│           │
│  └──────────┘  └──────────┘            │
└─────────────────────────────────────────┘
         ↓ 统一调用
─────────────────────────────────────────┐
│         LLM Gateway                      │
│  (OpenAI / Claude / Qwen / 本地模型)     │
└─────────────────────────────────────────┘
```

### 关键设计原则

1. **AI 辅助而非替代**：所有 AI 输出都支持人工确认/修改
2. **可追溯**：AI 的每次调用都记录 prompt、响应、token 消耗
3. **可配置**：AI 能力可通过配置开关控制，支持降级到规则引擎
4. **成本可控**：设置 AI 调用预算上限，避免意外成本
