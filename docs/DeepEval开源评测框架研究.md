# DeepEval 开源评测框架 — 产品简介与功能模块架构

> **项目地址**：https://github.com/confident-ai/deepeval
> **Stars**：6k+
> **语言**：Python
> **许可证**：Apache 2.0
> **定位**：面向 LLM 应用的开源评测框架，类似 Pytest 但专为 AI 应用设计

---

## 一、项目简介

DeepEval 是由 Confident AI 团队开源的 LLM 评测框架，专为评估大语言模型应用而设计。它的核心理念是将 LLM 应用的测试体验做得像 Pytest 一样简单，同时内置了 50+ 开箱即用的评测指标。

### 核心价值

- **Pytest 风格测试**：用 `assert_test()` 编写评测用例，无缝集成 CI/CD
- **50+ 开箱指标**：覆盖 RAG、Agent、对话、安全、多模态等全场景
- **三种评测模式**：端到端黑盒、组件级、轨迹级评测
- **合成数据生成**：自动生成边界 case 数据集
- **本地优先**：评测在本地运行，数据不离开用户环境
- **Confident AI 集成**：可选连接云端 Dashboard 进行团队协作

### 适用人群

| 角色 | 使用场景 |
|------|----------|
| AI 工程师 | 评测 Agent/RAG/工具调用，编写行为测试 |
| 数据科学家 | 对比 Prompt/模型/数据集的实验 |
| QA 工程师 | 回归测试，确保 AI 行为不退化 |
| 技术 PM | 定义质量标准，追踪改进趋势 |

## 三、核心功能模块详解

### 3.1 评测指标体系（50+ 指标）

DeepEval 最核心的竞争力是其丰富的指标库，按应用场景分为 8 大类：

#### 3.1.1 通用指标

| 指标 | 说明 | 评测方式 |
|------|------|----------|
| **G-Eval** | 通用 LLM-as-Judge 评分，支持自定义评判标准 | LLM 评判 |
| **DAG** | 基于图的确定性 LLM-as-Judge 指标构建器 | 图结构编排 |
| **Hallucination** | 幻觉检测，验证输出是否与上下文事实一致 | LLM 评判 |
| **Toxicity** | 毒性检测，评估输出中的有害内容 | 分类器 |
| **Bias** | 偏见检测，识别性别/种族/政治偏见 | LLM 评判 |
| **Summarization** | 摘要质量，评估摘要的事实正确性和信息完整性 | LLM 评判 |
| **JSON Correctness** | JSON 格式校验，验证输出是否符合 JSON Schema | 确定性 |
| **Prompt Alignment** | Prompt 对齐度，衡量输出是否遵循指令 | LLM 评判 |

#### 3.1.2 Agent 指标（8 个）

| 指标 | 说明 |
|------|------|
| **Task Completion** | 任务完成度 — Agent 是否达成了目标 |
| **Tool Correctness** | 工具正确性 — 是否调用了正确的工具、传入正确参数 |
| **Goal Accuracy** | 目标准确度 — Agent 达成预期目标的精确程度 |
| **Step Efficiency** | 步骤效率 — 是否走了不必要的步骤 |
| **Plan Adherence** | 计划遵循 — Agent 是否按预期计划执行 |
| **Plan Quality** | 计划质量 — Agent 制定的计划是否合理 |
| **Tool Use** | 工具使用 — 工具调用的整体质量 |
| **Argument Correctness** | 参数正确性 — 工具调用参数的正确程度 |

#### 3.1.3 RAG 指标（6 个）

| 指标 | 说明 | 评测维度 |
|------|------|----------|
| **Answer Relevancy** | 答案相关性 | 生成质量 |
| **Faithfulness** | 忠实度 — 输出是否忠于检索上下文 | 生成质量 |
| **Contextual Recall** | 上下文召回 — 检索上下文与期望输出的匹配度 | 检索质量 |
| **Contextual Precision** | 上下文精确度 — 相关节点是否排名靠前 | 检索质量 |
| **Contextual Relevancy** | 上下文相关性 — 检索内容与输入的整体相关度 | 检索质量 |
| **RAGAS** | 综合指标 — 上述四项的平均值 | 综合 |

#### 3.1.4 多轮对话指标（5 个）

| 指标 | 说明 |
|------|------|
| **Knowledge Retention** | 知识保持 — 对话中是否保持事实信息 |
| **Conversation Completeness** | 对话完整性 — 是否满足用户需求 |
| **Turn Relevancy** | 轮次相关性 — 每轮回复是否持续相关 |
| **Turn Faithfulness** | 轮次忠实度 — 跨轮次的事实一致性 |
| **Role Adherence** | 角色遵循 — 是否始终保持设定角色 |

#### 3.1.5 MCP 指标（3 个）

| 指标 | 说明 |
|------|------|
| **MCP Task Completion** | MCP 任务完成度 |
| **MCP Use** | MCP 服务器使用效率 |
| **Multi-Turn MCP Use** | 多轮对话中的 MCP 使用评测 |

#### 3.1.6 多模态指标（5 个）

| 指标 | 说明 |
|------|------|
| **Text to Image** | 文生图质量（语义一致性 + 感知质量） |
| **Image Editing** | 图像编辑质量 |
| **Image Coherence** | 图像与文本的连贯性 |
| **Image Helpfulness** | 图像对理解的辅助效果 |
| **Image Reference** | 图像引用的准确度 |

## 四、代码示例速览

### 4.1 基础评测（Pytest 风格）

```python
import pytest
from deepeval import assert_test
from deepeval.metrics import GEval, FaithfulnessMetric
from deepeval.test_case import LLMTestCase

def test_rag_output():
    # 定义评测用例
    test_case = LLMTestCase(
        input="退货政策是什么？",
        actual_output="您有30天全额退款保障。",
        expected_output="我们提供30天全额退款服务。",
        retrieval_context=["所有客户享有30天全额退款。"]
    )
    
    # 运行评测
    assert_test(test_case, [
        GEval(name="正确性", criteria="判断输出是否与期望一致", threshold=0.7),
        FaithfulnessMetric(threshold=0.7),
    ])
```

### 4.2 Agent 轨迹评测

```python
from deepeval.tracing import observe, update_current_span
from deepeval.metrics import TaskCompletionMetric

@observe()
def agent_step(input: str):
    result = call_llm(input)
    update_current_span(test_case=LLMTestCase(
        input=input, actual_output=result
    ))
    return result

# 轨迹级评测
for golden in dataset.evals_iterator(metrics=[TaskCompletionMetric()]):
    agent_step(golden.input)
```

### 4.3 独立使用指标

```python
from deepeval.metrics import AnswerRelevancyMetric
from deepeval.test_case import LLMTestCase

metric = AnswerRelevancyMetric(threshold=0.7)
test_case = LLMTestCase(
    input="如何退货？",
    actual_output="您可以在30天内申请退款。",
    retrieval_context=["退货期限为30天。"]
)

metric.measure(test_case)
print(f"分数: {metric.score}")
print(f"理由: {metric.reason}")
```

## 五、技术架构特点

| 特点 | 说明 |
|------|------|
| **本地优先** | 评测在本地运行，NLP 指标使用本地模型，数据不离开环境 |
| **LLM-as-Judge** | 大部分指标使用 LLM 作为评判器，支持任意 LLM 后端 |
| **高度模块化** | 每个指标可独立使用，无需完整框架 |
| **Pytest 原生** | 深度集成 Pytest，支持 `deepeval test run` 命令 |
| **异步支持** | 支持异步评测，提升大规模评测效率 |
| **缓存机制** | 内置缓存，避免重复 LLM 调用 |
| **并行化** | 支持并行评测多个用例 |
| **.env 自动加载** | 自动加载 .env.local / .env 配置 |
